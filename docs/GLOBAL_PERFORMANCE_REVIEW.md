## Supporting CPU/cache options

- Validate immutable look/person references once in a private prepared render packet and avoid correction work for exactly zero ownership/support, retaining public API validation/error behavior. Current skin people loop evaluates full correction even for zero weights. No epsilon cutoff or bounding-box clipping of nonzero soft edges. The previous per-person reuse prototype in SMART_PERSON_COLOR_REUSE.md was rejected after actual AE median637→645ms: do not reintroduce it based only on a microbenchmark.
- Split disk-read work from inference serialization with bounded per-key single-flight; current automatic miss lock encloses disk decode as well as model work. This can remove unrelated disk requests waiting behind an inference. Requires cancellation, clear-generation, ownership, duplicate-miss and model-permit tests. RAM-hit blocking was already fixed; do not call it still broken.
- After payload/hash costs are measured, consider reusable scratch buffers and indexed/batched quota maintenance. Current storage enumerates entry directories on every write. Do not remove checksums, semantic validation, atomic publication or crash recovery to improve timing.
- Multi-frame rendering, host-owned parallel rows, prepared-input reuse, CoreML compilation cache, full-file accelerated asset hashes and lossless disk compression already exist. More threads are not automatically faster on this16GiB unified-memory Mac. Keep AE scheduling ownership; no uncontrolled model pools.
- A full-clip preanalysis stage may improve interactive wait predictability, but it does not reduce total model work by itself. It also needs explicit source/upstream invalidation, cancellation and quota handling. Sparse keyframe analysis/propagation changes the accepted algorithm and is not the first safe optimization.
